# AI 量化研究平台 · 长期路线图（2026-08-30）

> 本文基于 [需求池 Backlog](../spec/需求池_AI股票分析系统_Backlog.md) 的 V2.5/V3 骨架、
> [V2 PRD](../spec/spec-003-V2量化研究平台（20260730）/spec-需求AI股票分析系统需求文档_PRD_V2.md) 的定位，
> 以及 2026-08 月研究产出（[IC 普查与数据质量报告](../backend/reports/step1_ic_survey_and_data_quality_20260821.md)、
> [全市场 RankIC 普查](../backend/reports/ic_survey_20260822.md)、Meta-Labeling 管线）制定。
> 定位是制定规划的依据，任务是落地规划的抓手；本文只做规划与拆解，不改代码。

## 一、平台定位（不变）

**个人级 A 股量化研究平台**：数据可信 → 研究可复现 → 策略可验证 → 组合可跟踪 →（远期）交易可闭环。

- 终局形态：一个能**自主完成"数据 → 因子 → 策略 → 回测 → 模拟盘 → 归因"全流程**的个人投研工作台，AI 承担分析与研究助理角色。
- 两条既定原则沿用：
  1. **先研究闭环，后交易闭环**（实盘始终是最后一步，且需合规评估）；
  2. **业务优先，架构缓做**（架构升级服务于业务规模，不为升级而升级）。
- AI 输出仅作研究参考，不构成投资建议。

## 二、现状盘点（截至 2026-08-30）

**已交付**：V1 主线（7-28）、V1.5 数据维度补齐（7-30）、V2 量化研究平台化（8-04，12 条需求全上线）。
功能面已覆盖：6 大类 34 因子 + IC 分析、8 策略 + 多因子打分、高级回测、组合管理、RAG + 4 Agent、新闻情绪。

**8 月进入研究深化期（V2.x，进行中）**：全市场 5 年日 K 补数（4,596 只零失败）、
全市场 IC 普查、Meta-Labeling 管线（规则出信号 + 随机森林做裁判）、组合级回测脚本；
工作区未提交内容为因子/K 线缓存与腾讯降级源稳定性打磨。

**研究结论揭示的关键事实**：A 股 2021-2026 是全面反转市场（amt20 / roc120 / rsi14 / hv20 全负向显著），
现有 `multi_factor.py` 若按直觉配置方向大概率是错的。

**当前最突出的短板**（均来自 step1 报告的自证，是下一阶段的主要矛盾）：

| # | 短板 | 影响 |
|---|---|---|
| 1 | 复权断裂（3,394 格 / 2,175 只，集中在 2026-06/07 分红高峰） | 正式回测前必须重刷，否则收益序列失真 |
| 2 | 幸存者偏差（股票池为当前快照，退市股缺失） | IC 与回测结果系统性偏乐观 |
| 3 | 未过滤 ST / 涨跌停不可成交样本 | 反转策略"跌停买不进"的最大执行风险未建模 |
| 4 | 行业分类仅 19 个一级类，无中性化 | 因子收益中混入行业/风格暴露 |
| 5 | amount/turnover 79% 缺失、576 格价格冻结、17 只错位 | 量类因子受限、脏数据未清 |
| 6 | 研究脚本未产品化（IC/Meta-Labeling/组合回测均在 scripts/） | 复盘不可复现、无法纳入日常调度 |

**核心判断**：平台当前瓶颈不是功能，而是**研究结论的可信度**。数据与回测严谨性不修复，
后续一切研究（包括 Meta-Labeling、模拟盘）都建立在有偏样本上。因此下一阶段的主线是"研究严谨化"，
而不是急着上 V2.5 架构或 V3 新功能。

## 三、长期路线图（四阶段 + 远期）

> 排期建议（单人节奏，可伸缩）：阶段一 ~3 周 → 阶段二 ~4 周 → 阶段三 ~3 周 → 阶段四 ~2 周 → 阶段五 2027 Q1 起滚动。
> 相对需求池原排期（V2.5 架构 → V3）有**两处调整**：一是把 V3 中的"模拟交易"提前到架构升级之前（理由见阶段三）；二是确认平台仅单人使用、无流量压力，V2.5 架构升级再裁剪为触发式（理由见阶段四）。

```text
V1/V1.5/V2 功能平台化（已完成）
        │
阶段一  V2.1 数据修复（~3 周）      —— 让数据可信
        │
阶段二  V2.2 研究闭环（~4 周）      —— 让结论可信、研究可复现
        │
阶段三  V3a 模拟盘闭环（~3 周）     —— 让策略可跟踪（BP-V3-005 提前）
        │
阶段四  V2.5 再裁剪·运行可靠性加固（~2 周）—— 让日常运行可靠
        │
阶段五  V3b AI 深度化（2027 Q1 起） —— 多 Agent / 自主投研 / 策略自优化
        │
远期    V3+ 实盘对接 / 多市场 / 组合风控（需合规与规模触发）
```

### 阶段一：V2.1 数据修复（让数据可信）

- **目标**：出回测报告时，可以声明"无幸存者偏差、无复权断裂、ST/涨跌停已处理、行业可中性化"。
- **不做**：新因子、新策略、新页面（数据质量日报除外）。
- **退出标准**：step1 报告中列出的四类数据问题全部闭环；每日数据质量巡检上线。

### 阶段二：V2.2 研究闭环（让结论可信、研究可复现）

- **目标**：把 8 月的"脚本级研究"升级为"平台级能力"——研究流程可复现、可调度、可交付报告。
- **内容**：按 IC 结论重构多因子方向与权重；回测计入成本与可成交性；分层回测/多 horizon IC/
  中性化产品化；组合级回测与 Meta-Labeling 从脚本进 service/API/前端。
- **退出标准**：产出一份《选股策略研究报告》（含分年度稳健性、成本后收益、明确局限性），
  全流程由平台功能而非一次性脚本支撑。

### 阶段三：V3a 模拟盘闭环（让策略可跟踪，BP-V3-005 提前）

- **为什么提前**：模拟盘是检验研究闭环的唯一试金石（回测 vs 实盘偏差），且不依赖任何架构升级
  （每日一次信号 + 撮合，现有 APScheduler + MySQL 完全够）。等架构升级再做会白白推迟反馈回路。
- **目标**：每日收盘后自动：生成信号 → 模拟撮合（次价成交、涨跌停/停牌约束、扣成本）→ 更新持仓净值
  → 输出与回测的偏差归因。
- **退出标准**：模拟盘连续运行 ≥ 4 周，净值/持仓/归因可查，出现 drift 能定位原因。

### 阶段四：V2.5 再裁剪·运行可靠性加固（让日常运行可靠）

> 再裁剪前提：平台仅本人单人使用、无并发流量压力，性能与部署类升级全部转**触发式**；
> 只保留与流量无关、关乎正确性与数据安全的两件事——任务链状态化、备份恢复。

对需求池 BP-V2-A01~A05 的**裁剪结论**（在单人使用前提下进一步收紧）：

| 原条目 | 结论 | 理由（含触发条件） |
|---|---|---|
| A01 Redis（缓存/限流/会话） | **转触发式** | 单人低并发下进程内缓存（cachetools）够用；采集侧限流是进程内问题。触发：随 Celery 进场时一并引入 |
| A02 Celery + Redis broker | **轻量替代，Celery 转触发式** | 日频管线一天一跑，真实痛点是失败可见性与长任务管理而非吞吐，用任务状态表 + 重试 + 告警覆盖。触发：任务需跨重启续跑、后台并发成为常态 |
| A03 ClickHouse / MySQL 分区 | **转触发式（暂缓）** | 日频全市场 5 年 ≈ 650 万行，MySQL 索引足够。触发：分钟 K 入库，或 K 线查询体感变慢（页面 > 3s） |
| A04 微服务拆分 | **不做**（维持原结论） | 模块化单体保持模块边界即可，拆分只增运维成本 |
| A05 K8s / 部署规范化 | **仅保留备份恢复** | docker-compose 服务化/健康检查服务于多服务多机场景，单人单机用不上；DB 备份 + 恢复演练属数据安全，与部署规模无关 |
| （补充）ES 全文搜索（BP-V2-007） | **暂缓**（维持原结论） | 用 MySQL ngram/前缀索引先覆盖个股/资讯检索 |

- **退出标准**：每日管线每步状态落库可查、失败当日告警；备份按策略产出且完成一次恢复演练；
  各触发式升级项的触发条件与验收标准一页存档。

### 阶段五：V3b AI 深度化（2027 Q1 起滚动）

- 多 Agent 协同（编排层，Agent 结论互为输入）→ AI Research Agent（主题→取数→跑因子→出报告）→
  策略自动优化（回测反馈自迭代，强制 walk-forward 防过拟合）→ 事件驱动策略框架。
- 前置条件：阶段一~三完成（AI 的输入数据与研究结论必须先可信，否则 AI 只是放大错误）。

### 远期（V3+，待触发）

- 实盘交易对接（券商 API，先过合规评估，维持 P2/构想）；
- 多市场（港股/美股）数据与因子适配；
- 组合级风控体系（Barra 式风险模型、行业/风格暴露约束）。

## 五、里程碑与风险

**里程碑**

| 时点 | 里程碑 |
|---|---|
| 2026-09 中 | M1 数据可信：四类数据问题闭环，质量日报上线 |
| 2026-10 底 | M2 结论可信：《选股策略研究报告》v1 发布（全平台功能支撑） |
| 2026-11 底 | M3 闭环打通：模拟盘上线并连续运行 |
| 2026-12 底 | M4 运行可靠：任务链状态化 + 备份恢复落地，架构升级全部转触发式 |
| 2027 Q1+ | M5 AI 深度化按特性滚动交付（T5.3 仅依赖阶段二，可提前启动） |

**主要风险与对策**

1. **数据源反爬/限连**（V1.5 已有先例）：多源冗余 + 降级链（东财→腾讯）持续建设，采集失败不阻断下游（已有 retry/补跑，保留）。
2. **研究结论 regime 依赖**（roc20 在 2021 转向的教训）：分年度稳健性验证强制为发布门槛（进 T2.8 报告模板）。
3. **功能快、验证松的历史节奏**：策略/因子上线前必须过回测门槛（含成本与可成交性约束），无门槛不上线。
4. **单人带宽**：任务表已按 S/M/L 排优先级，进度落后时优先砍各阶段 P2（T1.8、T4.3），不动数据修复与回测严谨化主线。
5. **实盘合规**：维持需求池结论——V3+ 立项前完成合规评估，在此之前一切输出仅研究参考。
