## 1. 系统定位

【确定】这是一个**面向 A 股市场的个人级量化研究平台**（项目自称 "AI Quant Platform"），由开发者本人为自己的投资研究而建，实际只有一名核心用户。它把"数据采集 → 行情展示 → AI 投研分析 → 量化因子/策略研究 → 历史回测 → 组合管理"整合成一条完整的个人投研工作台流水线，目标是"数据可信 → 研究可复现 → 策略可验证 → 组合可跟踪 →（远期）交易可闭环"。

它存在的理由【确定，ROADMAP 原文】：现有工具（同花顺/TradingView/聚宽/ChatGPT）各管一段，没有一个能让自己"自主完成数据→因子→策略→回测→归因全流程"的一体化工具；同时免费公开数据源（东方财富/腾讯/新浪）零散且不稳定，需要自建采集与治理层。

业务边界【确定】：

- **只做研究与模拟，不做实盘交易**——实盘对接是远期规划且需合规评估；
- 所有 AI 输出都强制附带"不构成投资建议"声明（代码中 RISK_DISCLAIMER 随处可见）；
- 平台明确为单人单机使用，刻意不引入 Redis / Celery / ClickHouse / 微服务 / K8s（均为触发式升级项）。

## 3. 核心功能

### 行情数据采集与治理（对用户透明，主要由定时任务驱动）

- 全市场日 K 线增量同步（每个交易日 17:30 自动跑，失败 23:00 自动重试，服务重启后自动补账）
- 近 5 年全市场历史 K 线低频轮询补数（已完成 4596 只）
- 股票池/指数/市场情绪/北向资金/个股资金流/板块/龙虎榜/财务指标 的每日定时采集
- 退市股名单（周更）、行业成分映射（周更）
- 数据修复能力：复权因子体系、价格冻结/错位修复、交易状态标注（ST/停牌/一字板）
- 每日数据质量巡检（次日早 8 点扫描复权断裂/缺失/冻结）

### 行情展示与市场情绪（看盘）

- 查看大盘总览（涨跌家数、涨停/跌停数、炸板率、连板高度等情绪指标）
- 搜索并查看个股详情：K 线、MA/MACD/RSI/KDJ/BOLL 等指标、筹码分布、资金流向、所属行业
- 浏览板块热度与板块内个股梯队
- 查看龙虎榜榜单、个股上榜记录、营业部席位明细
- 查看北向资金流入流出

### AI 投研分析

- 对任意个股发起 AI 分析（流式输出基本面/技术面/资金面/风险/综合评分）
- 生成板块分析、大盘分析、每日复盘、个股推荐四类 Agent 报告（定时自动生成，也可手动触发）
- 与 AI 助手多轮对话（SSE 流式），提问"今天为什么机器人板块涨""龙头股是谁"等
- 上传文档到知识库，AI 问答自动走 RAG 检索并标注引用来源

### 量化因子研究

- 查看因子字典（34 个因子，6 大类：趋势/动量/波动率/成交量/基本面/情绪）
- 对个股计算因子值
- 查看因子 IC 序列（因子有效性证据）
- 多因子打分选股（输入股票池和日期，输出排名）

### 策略与回测

- 查看 8 个内置策略（MA/EMA/MACD/趋势/龙头/打板/低吸/突破）
- 配置回测（策略、时间范围、初始资金）并运行
- 查看回测结果：收益统计、回撤曲线、持仓明细
- 对组合跑回测

### 机器学习辅助

- 运行 Meta-Labeling 管线：对比"原始规则信号"与"模型过滤后信号"的绩效差异

### 数据质量与运维管理（Admin 页）

- 查看数据源列表与连通性测试
- 查看/手动触发所有采集任务，查看任务运行日志与失败明细
- 查看数据质量日报与趋势
- 用户管理（查看/禁用用户）

## 4. 核心业务实体

围绕"数据 → 研究结论 → 决策"这条主线，核心实体链为：

```text
股票池（全市场快照，含退市股）
   → 日K线（不复权价 + 复权因子 + 交易状态）
   → 因子值 → IC 检验 → 多因子打分
   → 策略信号 → 回测运行/结果
   → 组合（持仓）
   → AI 分析/Agent 报告（辅助人做判断）
```

关键实体解释：

- **日 K 线**（`sa_kline_daily` + 复权因子 `sa_adjust_factor` + 交易状态 `sa_daily_trade_status`）【确定】：系统最核心的资产。V2.1 特意拆成"原始价 + 复权因子 + 可交易标记"三件套，因为回测可信度完全依赖它。约 650 万行（5 年全市场）。
- **股票池/股票生命周期**（`stock_pool` / `sa_stock_lifecycle`）【确定】：定义"研究在某个历史时点能买什么"，用于消除幸存者偏差（退市股必须入池）。
- **因子**（`sa_factor_value` / `sa_factor_ic`）【确定】：从 K 线派生的"选股特征"，IC 是因子预测力的量化证据——这是"研究可复现"的核心载体。
- **回测运行**（`sa_backtest_run` / `sa_backtest_result`）【确定】：一次策略验证的完整快照，是"策略可验证"的产出物。
- **组合**（`sa_portfolio` / `sa_portfolio_holding`）【确定】：用户手工维护的持仓集合，未来模拟盘/净值跟踪的锚点。
- **AI 分析与 Agent 报告**（`sa_ai_analysis` / `sa_agent_report`）【确定】：LLM 对数据的解读产物，定位是"研究参考"，永远带免责声明。
- **知识库**（`sa_knowledge_doc` / `sa_knowledge_chunk`）【确定】：用户上传的研报/资料，切块向量化后供 RAG 问答引用。
- **任务日志与质量检查**（`sa_admin_task_log` / `sa_data_quality_check`）【确定】：运维实体，记录每次采集任务的成败与每日数据体检结果。

实体关系：**数据类实体（K线/资金/板块/龙虎榜）是原料 → 因子/IC 是加工品 → 策略/回测是验证品 → 组合是应用品；AI 实体（分析/报告/对话/知识库）横跨其上做解读。**

## 5. 典型使用场景

### 场景 1：每日收盘后自动数据入库（无人值守）

- **使用者**：系统（APScheduler 定时任务）
- **触发条件**：每个交易日 16:25~19:30，按预设时间链自动触发
- **用户目的**：保证第二天开盘前，全市场最新数据已完整入库

```text
16:25 刷新股票池（全市场快照）
 ↓
16:35~17:10 同步指数 / 市场情绪 / 北向资金 / 个股资金流 / 板块
 ↓
17:30 全市场日K增量同步（近7天，逐只拉取，失败记录）
 ↓
18:00 龙虎榜同步 → 18:10/18:20 大盘Agent、复盘Agent自动生成当日报告
 ↓
19:00 交易状态标注 → 19:30 财务指标刷新
 ↓
23:00 失败重试（若当日行数远低于基线则整体重跑）
 ↓
次日 8:00 数据质量巡检（复权断裂/缺失/冻结扫描落库）
```

- **最终结果**：数据资产每日自动滚动更新，AI 当日复盘报告自动生成，数据异常次日可在 Admin 页看到。【确定】

### 场景 2：盘后看盘复盘

- **使用者**：平台主人（个人投资者）
- **触发条件**：收盘后或晚上，想了解"今天市场怎么样"
- **用户目的**：快速掌握市场情绪、热点板块、资金动向、龙虎榜动向

```text
打开平台首页（/market）
 ↓
看大盘总览（涨跌家数/涨停跌停/炸板率/连板高度/成交额）
 ↓
看北向资金、热门股、市场情绪指标
 ↓
钻入板块页看板块热度与龙头 → 钻入个股详情看K线/资金/筹码
 ↓
查看龙虎榜，点开个股看席位明细
 ↓
阅读当日自动生成的"每日复盘报告"（AI Agent 18:20 已生成）
```

- **最终结果**：一次完整的盘后复盘，形成对明日市场的判断素材。【确定】

### 场景 3：对某只股票做 AI 深度分析

- **使用者**：平台主人
- **触发条件**：看中某只股票（如从板块/龙虎榜发现），想快速全面了解
- **用户目的**：几分钟内获得该股的基本面/技术面/资金面综合分析

```text
进入个股详情页 → 点"AI分析"
 ↓
系统自动汇集该股近期K线、MACD等指标、PE/PB
 ↓
拼装 prompt 调用 DeepSeek，流式输出分析
 ↓
LLM 输出结构化结果（各维度分析 + 综合评分 + 风险提示）
 ↓
分析结果落库，可回看历史分析
```

- **最终结果**：一份带免责声明的个股 AI 分析报告。【确定】

### 场景 4：验证"某个选股想法是否有效"（因子研究）

- **使用者**：平台主人（量化研究者角色）
- **触发条件**：产生一个选股假设，如"低波动股票是否更抗跌"
- **用户目的**：用数据和统计证据检验因子有效性，而非凭感觉

```text
因子页查看因子字典（如 hv20 波动率因子）
 ↓
计算因子值序列
 ↓
查看 IC 序列（因子值与未来收益的秩相关性）
 ↓
多因子打分：选定因子与权重，对股票池打分排名
 ↓
（进阶）运行 Meta-Labeling：让随机森林过滤低质量信号，对比前后绩效
```

- **最终结果**：得到"这个因子/组合在历史上是否有预测力"的量化结论。已知研究结论：A 股 2021-2026 是全面反转市场，动量类因子全负向显著——这类洞见正是该场景的产出。【确定】

### 场景 5：回测一个策略

- **使用者**：平台主人
- **触发条件**：有了候选策略（如 MACD 金叉买入），想知道历史上赚不赚钱
- **用户目的**：用历史数据模拟交易，评估策略可行性

```text
回测页选择策略（8个内置之一或多因子打分）
 ↓
配置时间范围、初始资金、标的
 ↓
提交回测 → 引擎加载历史K线 → 逐日计算信号 → 模拟买卖
 ↓
产出收益率/最大回撤/夏普/胜率、收益与回撤曲线、逐期持仓
 ↓
结果落库（sa_backtest_run）可随时回看
```

- **最终结果**：一份策略历史绩效报告，作为"上/不上这个策略"的决策依据。【确定】

### 场景 6：维护股票组合并验证组合

- **使用者**：平台主人
- **触发条件**：研究结论转化为实际关注的持仓组合
- **用户目的**：集中管理自己关注/持有的股票，并对组合整体跑回测

```text
创建组合 → 添加/调整持仓
 ↓
对组合发起回测
 ↓
查看组合级净值、收益、持仓变化
```

- **最终结果**：组合层面的历史验证；为未来模拟盘跟踪打基础。【确定】

### 场景 7：向 AI 助手提问（RAG 问答）

- **使用者**：平台主人
- **触发条件**：随时有投研问题，如"今天为什么机器人板块上涨？"
- **用户目的**：用自然语言获取基于数据的解答

```text
AI助手页发起/继续会话
 ↓
系统先在知识库（用户上传的研报等）做向量检索
 ↓
命中 → 检索片段+问题一起给 DeepSeek，回答标注引用来源
未命中 → 普通对话模式
 ↓
SSE 流式返回 + 强制风险提示，会话历史落库
```

- **最终结果**：带来源标注的回答；多轮会话可回溯。【确定】

### 场景 8：数据出问题时诊断与修复

- **使用者**：平台主人（运维者角色）
- **触发条件**：发现 K 线缺数/价格异常/复权断裂，或数据源被反爬封禁
- **用户目的**：让数据恢复可信——ROADMAP 明言"数据不修复，一切研究建立在有偏样本上"

```text
Admin 页查看数据质量日报（断裂/冻结/缺失清单）
 ↓
查看任务运行日志定位失败环节
 ↓
手动触发重跑（任务级），或测试数据源连通性
 ↓
（必要时）跑 scripts/ 下的修复脚本（腾讯降级补数/复权检查/单位修复）
```

- **最终结果**：数据问题闭环；这是当前版本（V2.1）的主线工作。【确定】

### 场景 9：构建私有投研知识库

- **使用者**：平台主人
- **触发条件**：积累了研报、公告、笔记等资料
- **用户目的**：让 AI 问答基于自己的资料回答，而非凭空生成

```text
上传文档 → 自动切块 → 向量化入库
 ↓
之后所有 AI 问答自动优先检索知识库
 ↓
可管理（查看/删除）知识库文档
```

- **最终结果**：一个个人投研 RAG 知识库。【确定】

### 场景 10：补充历史数据（长周期研究前置）

- **使用者**：系统（低频轮询任务）+ 主人（监控进度）
- **触发条件**：开启 history_backfill 后每 10 分钟一个 tick
- **用户目的**：把全市场近 5 年日 K 补齐，使长周期回测/IC 研究有足够样本

```text
每10分钟tick（避开每日同步静默窗口，限速防封）
 ↓
按批拉取个股5年历史K线，断点续传
 ↓
全部达标后任务自动停
```

- **最终结果**：4596 只股票 5 年历史零失败补齐（已完成，git log 有记录）。【确定】

## 6. 核心业务流程

### 流程一：每日数据流水线（系统主心跳）【确定】

```text
交易日收盘
    ↓
刷新股票池（定义"全市场"）
    ↓
同步各维度数据（指数/情绪/资金/板块/龙虎榜/日K/财务）
    ↓
失败自动重试 + 行数基线自检（重启也不丢）
    ↓
数据落库后触发 AI Agent 生成当日大盘/复盘报告
    ↓
次日早晨质量巡检，异常落库供 Admin 查看
```

### 流程二：个股 AI 分析流程（人机交互）【确定】

```text
用户选择个股发起分析
    ↓
系统汇聚结构化数据上下文（K线/指标/估值）
    ↓
构建 prompt → 调用 DeepSeek（流式）
    ↓
解析为结构化结果（评分+风险）
    ↓
落库 + 流式返回前端，附风险提示
```

### 流程三：研究验证流程（量化研究主链路）【确定】

```text
选股假设
    ↓
在 5 年全市场数据上计算因子
    ↓
IC 检验（含分年度稳健性）
    ↓
多因子打分 → 生成信号
    ↓
（可选）Meta-Labeling 随机森林过滤信号
    ↓
回测（含成本/可成交性约束）
    ↓
分年度稳健性达标 → 结论进入《选股策略研究报告》
    ↓
不达标 → 假设证伪，回到起点
```

### 流程四：数据修复流程（V2.1 当前主线，异步+人工）【确定】

```text
质量巡检发现异常（复权断裂/价格冻结/错位）
    ↓
Admin 页查看明细清单
    ↓
修复脚本/rebuild 任务低频轮询重灌（防反爬）
    ↓
复检通过 → 数据恢复可信
```

### 异步/定时/消息机制说明【确定】

系统**没有 MQ**（刻意决策，ROADMAP 明确 Celery/Redis 转触发式）；异步性全部由 APScheduler 定时任务 + 启动时补账线程 + SSE 流式响应构成。

## 7. 系统上下游关系

【确定】这是一个**终端型系统**：没有其他系统调用它（唯一上游是浏览器前端），它也不向任何业务系统输出；它消费免费公开数据源和 LLM API，产出全部进入自有 MySQL 和前端页面。

```text
东方财富(AkShare) ──┐  主K线源（有限速/重试/UA轮换防反爬）
腾讯财经 ──────────┼──→  Python 系统(FastAPI)  ──→  阿里云 RDS MySQL（唯一持久层）
新浪财经 ──────────┘       │                        （K线/因子/回测/AI报告等40+表）
（交易日历/降级源）         ├──→  DeepSeek LLM API
                          │      （个股分析/Agent报告/对话/RAG）
                          ↓
                   React SPA 前端（唯一消费端，15个页面）
```

- **数据入口**：全部来自免费公开数据源，拉取式（pull），采集侧有"东财→腾讯"降级链与反爬对抗（501 冷却、限速、UA 轮换）【确定】
- **同步调用**：前端↔后端 REST API；后端↔LLM API；后端↔数据源抓取【确定】
- **异步机制**：APScheduler 定时任务（每日管线+周任务+轮询补数），无消息队列【确定】
- **数据出口**：仅前端展示与 MySQL 存储；无对外推送/开放 API【确定】

## 8. 从"用户视角"重新解释系统

假设你是新加入的开发，5 分钟版解释：

**它是谁**：老板（也是唯一用户）自己为自己搭的"A 股量化研究工作台"——你可以理解为"把同花顺的看盘、聚宽的回测、ChatGPT 的投研问答，拼成一个私人一体化平台"。后端是 FastAPI 单体 + MySQL，前端 React，AI 用 DeepSeek，数据全部从东方财富/腾讯等免费源自己爬。

**它解决什么问题**：做量化研究需要"数据可信、研究可复现、策略可验证"。免费数据源零散不稳定（还会封 IP），商业平台又不开放全流程，所以自己建：每天收盘后系统自动把全市场 4600 只股票的行情、资金、板块、龙虎榜数据收进自己的数据库，再用这些数据做因子研究、跑回测、让 AI 写复盘报告。

**用户怎么用它**：白天看盘（大盘情绪/板块/个股/龙虎榜）→ 收盘后系统自动更新数据并生成 AI 复盘 → 晚上做研究（算因子 IC、跑策略回测、问 AI 助手）→ 有结论了建组合跟踪。数据坏了就去 Admin 页看质量日报、手动重跑任务。

**最重要的三条潜意识规则**：

1. 一切 AI 输出只是研究参考，代码里强制加免责声明；
2. 不做实盘，实盘是远期且要过合规；
3. 数据可信度 > 功能数量——当前版本（V2.1）整个阶段都在修数据问题，因为"数据有偏，研究全错"。

## 10. 存疑点核实结果（2026-09-05 与平台主人确认）

初版分析报告留下三个存疑点，已全部核实：

| 项目 | 状态 | 说明 |
| --- | --- | --- |
| 告警通知渠道 | 【确定·用户确认】未接入 | 质量巡检结果只落库 + Admin 页可视化，无邮件/站内等任何触达方式 |
| 分钟 K 数据 | 【确定·用户确认】未使用 | `sync_minute.py` 与 `SaMinutePrice` 模型存在但未实际启用；大规模入库是引入 ClickHouse 的触发条件（ROADMAP A03） |
| 新闻情绪 | 【确定·代码核实】孤岛功能 | 详见下节 |

### 新闻情绪功能专项核实

**已建成的部分**：

- **数据模型**：`sa_news_sentiment` 表，每条资讯一行——标题/正文/来源/发布时间 + LLM 情绪分（-1~+1，3 位小数）+ 80 字摘要 + 关联个股代码 + 关联板块。
- **采集**：`sync_news.py` 经 AkShare 抓取财联社电报 + 东财全球快讯，按（来源+标题+发布时间）幂等去重入库；单源挂掉不影响另一源。
- **打分**：`news_service.score_sentiment` 调 DeepSeek 输出严格 JSON，解析容错，失败留 NULL 不阻塞。
- **API**：`GET /api/v1/news`（按个股/板块/日期过滤）、`POST /api/v1/news/sync`（手动触发，`score` 参数默认 false 即只采集不打分）。

**断开的三个环节**：

1. **无定时采集**：调度器中没有 news 任务。每天 16:45 的 `sentiment_sync` 是"市场情绪统计"（涨停数/炸板率，写 `sa_market_sentiment`），与新闻情绪是两回事。新闻数据只有手动调 `POST /news/sync` 才会进来。
2. **无前端页面**：前端 `api/news.ts` 封装存在，但没有任何页面 import 它。Analysis 页的"消息面"评分是 AI 个股分析输出维度，但 `stock_agent` 喂给 LLM 的上下文只有 K 线/技术指标/PE/PB，不含已采集新闻——该"消息面"基本是 LLM 泛泛而谈。
3. **零下游消费**：全库 `SaNewsSentiment` 只有模型定义、采集、服务、API 四处引用。情绪因子（`factor/sentiment.py`）用涨停家数/炸板率/北向/连板高度，不含新闻情绪；5 个 Agent、多因子打分、回测均不读这张表。

**业务判断**：对应 V2 需求 BP-V2-008，按"采集→打分→查询"最小闭环交付，但没接到任何使用场景上。按 ROADMAP，新闻情绪深化（接入 Agent 上下文、情绪因子化）排在 V3b AI 深化阶段（2027 Q1+）。当前实际价值为零，除非手动 curl 触发采集再查库。

## 最终结论

### 一句话定位

> 【确定】一个面向 A 股的**个人级量化研究平台**：自动采集全市场行情数据，提供看盘、AI 投研、因子研究、策略回测与组合管理的一体化私人投研工作台。

### 核心价值

> 【确定】让一个人能独立完成"数据可信 → 研究可复现 → 策略可验证 → 组合可跟踪"的完整量化研究闭环，用免费数据源 + LLM 替代商业终端与人工分析。

### 主要使用者

1. 【确定】平台主人本人（投资者+量化研究者+运维者三重角色，系统按单人使用设计）
2. 【推测】支持多用户注册（auth/用户管理/配额限流存在），但不排除仅自用预留能力

### 核心业务域

1. 行情数据采集与治理（核心地基）
2. 行情展示与市场情绪（看盘）
3. AI 投研分析（5 Agent + RAG + 对话）
4. 量化因子研究（34 因子 + IC + 打分）
5. 策略与回测（8 策略 + 回测引擎）
6. 组合管理 / ML 辅助 / 运维管理（辅助）

### 核心功能

1. 全市场日 K 与多维数据每日自动同步（含失败重试、断点补账、5 年历史回补）
2. 大盘/板块/个股/龙虎榜/北向资金看盘与情绪指标
3. AI 个股分析、四类 Agent 自动报告、RAG 知识库流式问答
4. 因子计算 → IC 检验 → 多因子打分选股
5. 策略回测（收益/回撤/持仓）与组合回测；Meta-Labeling 信号过滤
6. 数据质量巡检 + 任务运维 Admin

### 最典型使用场景

1. 每日收盘后数据自动入库与 AI 复盘自动生成（无人值守）
2. 盘后复盘看盘：市场情绪 → 板块 → 个股 → 龙虎榜
3. 对个股发起 AI 深度分析
4. 用 IC 检验因子有效性、多因子打分验证选股假设
5. 回测策略/组合，决定策略去留
6. 数据异常时在 Admin 诊断并修复

### 核心业务流程

```text
【数据主流程】公开数据源 → 定时采集(含降级/重试) → MySQL 治理入库 → 质量巡检
【研究主流程】因子计算 → IC检验 → 多因子打分 → (ML过滤) → 回测 → 稳健性结论
【AI主流程】数据上下文 → DeepSeek → 分析/报告/对话(强制免责声明) → 落库展示
```

### 系统上下游

```text
东财/腾讯/新浪(免费公开数据源) + DeepSeek API
        → stock-platform(FastAPI 单体 + APScheduler)
        → 阿里云 RDS MySQL + React 前端（终端型系统，无对外输出）
```
