> 版本：V3a 模拟盘闭环（让策略可跟踪）
> 对应 ROADMAP：阶段三 T3.1 / T3.2 / T3.3 / T3.4 / T3.5 / T3.6（原 BP-V3-005「模拟交易」提前落地）
> 立项日期：2026-09-06
> 前置：V2.2 研究闭环（阶段二）已全量交付——多因子打分 V2（v2_reversal 预设）、组合级回测（T+1 开盘撮合 + 全成本 + 可成交性）、成本模型、交易状态表均已上线（Backlog BP-V2.2-001~008 状态）。

## 一、项目背景（V3a 增量）

### 1.1 版本定位：为什么单开一个"模拟盘"版本，且放在架构升级之前

V2.2 交付后，平台已能在历史数据上回答"这个策略过去表现如何"，但**无法回答"这个策略现在表现如何"**。组合回测的结论（v2_reversal 两年 +91.96%）建立在"信号日收盘可知全部数据、次日开盘必可成交"的理想假设上，真实世界里两者都可能不成立：

1. **数据到达偏差**：每日 17:30 K 线同步可能部分失败，实际可用的股票池与回测假设不同；
2. **执行偏差**：次日开盘的流动性、一字板、停牌会导致目标组合买不齐、卖不掉；
3. **Regime 偏差**：回测是"过去时"，因子健康度巡检已显示 4/5 因子近季告警——策略当前是否还有超额，只有前向跟踪能回答。

模拟盘是检验研究闭环的**唯一试金石**：同一套打分管线、同一套撮合规则，从"批量回放历史"变成"每日增量推进"，两者净值之差（drift）就是研究假设与现实之间的全部距离。ROADMAP 已论证它不依赖任何架构升级（每日一次信号 + 撮合，现有 APScheduler + MySQL 足够），故提前至阶段三，先于 V2.5。

### 1.2 版本目标（V3a 全量 6 项）

> 每日收盘后自动完成：生成信号 → 模拟撮合（次日开盘价、可成交性约束、扣成本）→ 更新持仓净值 → 输出与回测的偏差归因。全程无人值守，drift 可定位。

- **T3.1 模拟账户模型**：账户 / 订单 / 成交 / 持仓快照 / 净值快照五张表（`sa_paper_` 前缀），Alembic 迁移。
- **T3.2 信号→订单生成器**：每日收盘后按账户配置（预设因子 / top_n / 调仓频率 / 治理开关）多因子打分生成目标持仓，diff 当前持仓产出调仓订单；挂调度。
- **T3.3 模拟撮合引擎**：次日开盘价成交、一字板/停牌买跳过卖顺延、整手、全成本模型；撮合核心与组合回测引擎共用同一套函数（零漂移设计锚点）；除权事件按复权因子表调整持股数。
- **T3.4 净值与归因**：每日净值曲线（vs 基准）、收益分解（选股/现金拖累/成本）、**回测 vs 模拟盘 drift 对比**（周收益差 / 持仓重合度 / 按股票分解）。
- **T3.5 模拟盘前端页**：账户总览、当前持仓、历史调仓、净值 vs 回测对比图。
- **T3.6 监控告警**：数据缺失 / 信号异常 / 回撤阈值告警落库 + admin 可视 + 日报摘要（站内渠道，邮件为 P2）。

### 1.3 成功标准（= ROADMAP 阶段三退出条件的工程子集）

1. 模拟账户创建后，每日 `paper_tick` 自动完成"撮合昨日订单 → 生成今日信号 → 收盘估值 → 告警检查"，无需人工干预；同日重复执行幂等（不产生重复成交）；
2. 成交价格 = 信号次日开盘价，成本模型数值与组合回测逐项一致（测试锁定）；涨停买单跳过、跌停卖单顺延有测试锁定；
3. **零漂移验证**：用历史区间数据逐日回放模拟盘引擎，与 `run_mf_backtest` 同参数结果净值逐日一致（容差内）——证明 drift 对比口径成立；
4. 净值 / 持仓 / 调仓 / 成交 / drift 全程 API + 页面可查；
5. 连续运行 ≥ 4 周出现 drift 时能定位到"数据差异 / 执行差异 / 成本差异"之一（M3 里程碑的运营验收，非代码条件）。

### 1.4 AI 输出声明（沿用 V2）

模拟盘所有输出（净值 / 归因 / drift）均为研究跟踪用途，不构成投资建议；模拟成交不代表真实可执行价格与容量。

## 二、总体架构（V3a 增量）

### 2.1 技术栈（无新增组件）

FastAPI + APScheduler + MySQL + 既有向量化研究引擎。维持模块化单体，不引入 Redis / Celery / 消息队列（触发式升级结论不变）。每日一次 `paper_tick`（20:00）为全量增量节奏，无需事件驱动。

### 2.2 关键架构决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 撮合引擎 | **从 `portfolio_backtest_service` 抽取共享撮合层**（开盘价撮合 / 可成交性 / 整手 / 成本），回测与模拟盘共用 | drift 对比只有在"同一套撮合代码"上才有意义；零漂移测试可锁定抽取过程不改变回测行为 |
| 推进模型 | 单账户单日状态机：`pending 订单 → 次日撮合 → 持仓/现金 → 净值快照`，每日一 tick | 与回测的批量回放同构；停机可按日补跑，订单状态机保证幂等 |
| 价格口径 | 撮合/估值价格与组合回测同源（当前 `daily_prices` qfq；`kline_source` 切换后随读取层统一切换） | 与回测可比性优先；不单独维护模拟盘价格路径 |
| 除权事件 | 持仓股除权日按 `sa_adjust_factor` 因子跳变调整持股数，缺因子行则告警并暂停该股买卖 | 长周期持仓必须处理送转/分红，否则净值出现虚假跳亏；回测短窗口容忍的问题在模拟盘不可容忍 |
| 告警 | 复用 `sa_data_quality_rule/check` 表族（`check_name='paper_health'`，`metric_name` 编码账户），同 factor_health 模式 | 零新表；admin 质量页模型直接复用 |
| 任务链 | `paper_tick` 注册为 admin 任务（`sa_admin_task_log`），补跑区间 > 5 交易日走 `_LONG_TASKS` 异步链路 | 与既有 V2.1 长任务框架一致，前端已有轮询模式 |

### 2.3 表结构变更（Alembic，一张迁移）

```text
sa_paper_account   账户：name(UK)、config JSON(预设/因子/top_n/频率/治理/成本)、
                   initial_cash、cash、status(active|paused|stopped)
sa_paper_order     订单：account_id、signal_date、exec_date、stock_code、side、
                   target_weight、shares、status(pending|filled|skipped|deferred|
                   cancelled)、fail_reason、filled_trade_id
                   UK(account_id, signal_date, stock_code, side)
sa_paper_trade     成交：account_id、order_id、trade_date、stock_code、side、
                   price、shares、amount、commission、stamp_duty、transfer_fee
sa_paper_position  持仓日快照：account_id、trade_date、stock_code、shares、
                   close_price、market_value   UK(account_id, trade_date, stock_code)
sa_paper_nav       净值日快照：account_id、trade_date、cash、market_value、
                   total_asset、nav、daily_ret、benchmark_close、benchmark_nav、
                   drawdown                       UK(account_id, trade_date)
```

不改动任何既有表；告警复用质量表族（见 2.2）。

### 2.4 每日时间线（与既有调度衔接）

```text
T 日 16:25  pool_sync（股票池）        16:35  index_sync（基准指数）
T 日 17:30  daily_k_sync（日 K）       19:00  trade_status_sync（交易状态）
T 日 20:00  paper_tick（本版本新增，单 job 串行四段）：
  ① 撮合段  处理 T-1 信号的 pending 订单 → T 日开盘价成交（一字板/停牌规则）→ 成交落库、持仓/现金更新
  ② 信号段  当日数据完备性守卫 → 多因子打分（T2.1 管线 + 治理开关）→ 目标持仓 diff → 生成 T+1 订单
  ③ 估值段  T 日收盘价估值（停牌 ffill）→ 净值快照（含基准）
  ④ 告警段  数据缺失/信号异常/回撤阈值 → paper_health 落库
```

非调仓日跳过 ② 的订单生成，①③④ 照常；周末/节假日整 tick 跳过（复用交易日历判断）。

## 三、V3a 功能范围

### 3.1 账户与撮合

#### BP-V3a-001 · 模拟账户模型【P0】（ROADMAP T3.1）

**用户故事**：作为策略研究者，我要创建一个配置明确（因子预设、top_n、调仓频率、成本参数、治理开关）的模拟账户，作为长期跟踪的主体。

**需求点**：
1. 账户 CRUD：创建（必填 name、config；初始资金默认 100 万）、暂停/恢复、终止；暂停期间不生成新信号、不执行撮合，净值冻结。
2. config 落库为 JSON，字段与 `run_mf_backtest` 入参对齐（preset / factors / top_n / freq / cost / pool / 样本过滤 / neutralize / liquidity_top_k / benchmark），保证 drift 对比时可原样复跑回测。
3. 五张表 + 唯一键（见 2.3）；订单状态机：`pending → filled | skipped | deferred | cancelled`。

**验收标准**：迁移可执行可回滚；重复创建同名账户被 UK 拒绝；订单/成交/持仓/净值按 UK 幂等 upsert。

#### BP-V3a-002 · 信号→订单生成器【P0】（ROADMAP T3.2，依赖 T2.1 已交付）

**用户故事**：作为策略研究者，我要让账户在每个调仓日收盘后自动按多因子打分生成目标持仓，并与当前持仓 diff 出调仓订单，而非人工选股。

**需求点**：
1. 调仓日判定：freq='W' | 'M' | N 交易日，规则与组合回测 `_rebalance_schedule` 一致（周/月取最后一个交易日）。
2. 目标持仓 = 治理后的池（PIT ∩ 样本过滤 ∩ buy_tradable ∩ 流动性 top-K）→ 统一打分（direction + neutralize）→ top-N 等权。
3. diff 规则：目标有现无 → 卖单；现有目标无 → 买单；权重再平衡仅在偏离超阈值（默认 20%，参数化）时触发调单，避免整手取整造成的每日微调仓。
4. 数据完备性守卫：当日 K 线行数低于近期基线（复用 settled_counts 口径）→ 当日不生成信号、落 `data_incomplete` 告警、持仓不动，次日 tick 自然重试。

**验收标准**：合成数据下 diff 出的订单集合与手工推演一致；数据不完备日不产单；调仓日与非调仓日行为符合预期。

#### BP-V3a-003 · 模拟撮合引擎【P0】（ROADMAP T3.3，依赖 BP-001/002）

**用户故事**：作为策略研究者，我要订单按"次日开盘价、一字板/停牌约束、整手、真实费率"成交，让模拟持仓的每一笔都经得起与回测逐项对账。

**需求点**：
1. **共享撮合层**：从 `portfolio_backtest_service` 抽出开盘价撮合 / `sa_daily_trade_status` 可成交性 / 整手 / 成本计算为共享函数，回测与模拟盘同时调用；抽取后既有回测测试全绿（行为不变）。
2. 成交规则与回测逐字一致：买单 `buy_tradable=0` → 本期跳过（skipped）；卖单 `sell_tradable=0` → 每日顺延重试（deferred），顺延超 10 交易日落告警并继续持有；成交价 = 开盘价 ± 滑点；成本 = 佣金（最低 5 元）+ 印花税（卖）+ 过户费。
3. 资金约束：卖出先于买入；买单按等权目标资金量整手取整，现金不足按可用资金缩量，保留缓冲（默认 2%）。
4. **除权事件处理**：持仓股 `sa_adjust_factor` 当日跳变 → 按因子比调整持股数（qfq 估值口径下保持市值连续）；无因子行 → 告警并暂停该股交易，人工介入后恢复。
5. 幂等：订单 UK + 状态机保证同日重复 tick / 停机补跑不产生重复成交。

**验收标准**：涨停买跳过、跌停卖顺延、成本数值、整手取整均有测试锁定；除权日持股数调整后市值连续；零漂移测试（见 1.3-3）通过。

### 3.2 跟踪与诊断

#### BP-V3a-004 · 净值、归因与 drift 对比【P0】（ROADMAP T3.4，依赖 BP-003）

**用户故事**：作为策略研究者，我要每日看到账户净值与基准的对比、收益从哪里来（选股/现金/成本），以及模拟盘与同配置回测的偏差是多少、差在哪，从而判断研究结论是否在前向失效。

**需求点**：
1. 每日净值快照：total_asset = cash + Σ持仓市值（停牌 ffill 收盘价）；nav、daily_ret、drawdown；基准（默认 sh000001）同日归一净值。
2. 收益分解（累计口径）：超额收益 = 模拟盘累计 − 基准累计，拆为 **成本拖累**（累计费用/初始资金）、**现金拖累**（现金比例 × 基准收益的累计近似）、**选股贡献**（残差）；当前等权近似满仓策略下择时项≈现金拖累，框架保留字段。
3. **drift 对比**：对账户 config 在重叠区间调 `run_mf_backtest`（复用既有服务，结果照常落 `sa_backtest_run`）→ 对齐交易日输出：周频收益差序列、累计净值差、换手率差、每调仓日 top-N 持仓重合度（Jaccard）、按股票分解的收益差贡献（模拟独有 / 回测独有 / 重合）。
4. drift 计算即时执行不落库（两侧净值均已各自落库），单次请求限单账户单区间。

**验收标准**：资产守恒（total_asset 变动 = 当日持仓盈亏 − 当日成本，测试锁定）；归因三项之和≈超额（容差 1e-6）；drift 接口在零漂移数据下返回全零差序列。

#### BP-V3a-005 · 模拟盘前端页【P1】（ROADMAP T3.5，依赖 BP-004）

**用户故事**：作为平台唯一用户，我要在一个页面看到模拟盘的全貌：净值曲线、当前持仓、历史调仓、以及与回测的对比，不用查库。

**需求点**：
1. 新增「模拟盘」页（导航入口）：账户选择器 + 创建对话框（预设/因子配置/top_n/频率/初始资金/治理开关）+ 暂停/终止操作。
2. 总览卡：净值、累计收益、年化、最大回撤、现金余额、持仓数；净值 vs 基准曲线（echarts）。
3. 当前持仓表（股票/股数/成本价/现价/市值/权重/浮动盈亏）与历史调仓表（信号日/执行日/方向/股数/成交价/费用/状态/原因，可展开订单）。
4. drift 卡：净值对比图（模拟 vs 回测）+ 周收益差柱图 + 持仓重合度 + 按股票差异表；触发按钮（选区间跑回测对比）。
5. 手动 tick（补跑）入口放 Admin 任务区（复用既有任务触发与轮询 UI）。

**验收标准**：从页面完成创建账户 → 次日 tick 后可见持仓与净值 → drift 卡可跑通；`npm run build` 通过。

#### BP-V3a-006 · 监控告警与日报【P1】（ROADMAP T3.6，依赖 BP-003）

**用户故事**：作为平台唯一用户，模拟盘无人值守运行，出问题（数据缺、信号空、回撤深）时要主动告诉我，而不是我打开页面才发现。

**需求点**：
1. 告警项（阈值入 `sa_data_quality_rule` 可改）：`data_incomplete`（信号日数据不完备）、`signal_anomaly`（目标持仓为空 / 单期换手 > 100%）、`drawdown`（净值回撤超阈值，默认 15%）、`sell_stuck`（卖单顺延超 10 交易日）、`corporate_action`（除权因子缺失）。
2. 告警落 `sa_data_quality_check`（`check_name='paper_health'`，`metric_name='<metric>:<account_id>`），admin 质量页模型复用；模拟盘页顶部展示未恢复告警。
3. 日报摘要（站内）：每交易日 tick 尾部落一条当日摘要行（净值/当日收益/成交笔数/费用/告警数），页面可按日翻阅；邮件渠道 P2 暂不做。

**验收标准**：构造数据触发五类告警各一条（测试）；阈值改规则表即生效；摘要行字段齐全。

## 四、非目标（本轮明确不做）

- 实盘交易对接（BP-V3-006，需合规评估，维持 P2/构想）；
- 盘中/分钟级撮合与实时行情——日频收盘信号 + 次日开盘撮合是回测同构口径，引入盘中会破坏 drift 可比性；
- Meta-Labeling 信号作为模拟盘信号源（打分管线先行；ML 信号接入待阈值校准迭代后另立）；
- 多账户策略横向对比平台化（支持多账户数据模型，但 UI 以单账户视图为主，单人无此需求）；
- 邮件/IM 告警渠道（P2）；Celery/Redis/ClickHouse（触发式结论不变）。

## 五、与需求池 / ROADMAP 的衔接

- 本 PRD 的 6 条需求登记为需求池 `BP-V3a-001~006`（新增 §六，原 §六~§八顺延）；
- 对应 ROADMAP 阶段三任务 T3.1~T3.6；原 `BP-V3-005（模拟交易）` 标注"已由 V3a 提前落地"，状态与拟入版本同步调整；
- 里程碑：M3 闭环打通（2026-11 底，模拟盘上线并连续运行 ≥ 4 周）；
- 后续衔接：阶段四 T4.1 任务链状态化将把 `paper_tick` 纳入统一管线状态记录（本轮先用 `sa_admin_task_log` 最小记录）。
