# AI股票分析系统需求文档（PRD V2.2）

> 版本：V2.2 研究闭环（核心五件套）
> 对应 ROADMAP：阶段二 T2.1 / T2.2 / T2.3 / T2.4 / T2.5
> 立项日期：2026-09-05
> 前置：V2.1 数据修复（阶段一）已交付——PIT 股票池、交易状态表、行业映射、中性化纯函数、样本过滤开关均已上线（Backlog BP-V2.1-004/005/006 状态）。

## 一、项目背景（V2.2 增量）

### 1.1 版本定位：为什么单开一个"研究闭环"版本

8 月研究深化期产出的全市场 IC 普查、Meta-Labeling 管线、组合回测全部以**一次性脚本**形态存在于 `backend/scripts/`，有三个致命问题：

1. **不可复现**：研究结论依赖脚本快照，数据更新后无法一键重跑；
2. **不严谨**：平台现有回测引擎无真实费率结构（无印花税/最低佣金）、无涨跌停/停牌可成交性约束、**仓位模型实际为每笔 1 股**（FixedSize 缺省，收益序列失真）；IC 计算不落库，`sa_factor_ic` 表自建立以来从未写入；
3. **不接线**：`neutralize.py`（行业+市值中性化纯函数，V2.1 已备）零调用方；`multi_factor.py` 的 direction/clip/中位数填充管线与 API 实际使用的弱版打分**双轨并存**。

V2.2 的使命：把"脚本级研究"升级为"平台级能力"——研究流程可复现、可调度、可交付报告。本轮交付核心五件套（T2.1~T2.5），T2.6~T2.8（Meta-Labeling 深化 / 因子健康度监控 / 《选股策略研究报告》）留待下一批次。

### 1.2 版本目标（V2.2 本轮）

> 让"打分 → 回测"这条主链路上的每一个数字都可信、可配置、可回看。

- **T2.1 多因子打分 V2**：因子方向配置化；按 IC 普查结论注册反转因子并内置 V2 预设（amt20/roc120/hv20/rsi14/skew20，全负向）。
- **T2.2 回测严谨化**：A股真实费率结构（佣金双边最低 5 元 + 印花税卖出单边 + 过户费 + 滑点）；涨跌停/停牌/一字板不可成交约束；修复 1 股仓位 bug。
- **T2.3 多 horizon IC + 分层回测**：IC 时序落库、1/5/10/20 日衰减曲线、因子五分位组合净值与多空价差，进因子研究页。
- **T2.4 中性化接线**：IC / 分层 / 打分三处统一支持行业、市值中性化开关。
- **T2.5 组合级回测产品化**：多因子打分 → 定期调仓 → 净值 vs 基准 / 换手 / 成本 / 持仓变化，service + API + 前端。

### 1.3 成功标准（= ROADMAP 阶段二退出条件的本轮子集）

1. `/factor/score` 支持 direction / top_n / preset，V2 反转预设可用；
2. 因子页可查看任一因子 1/5/10/20 horizon 的 IC 序列与衰减、五分位分层净值与多空价差，且 IC 结果已落库 `sa_factor_ic`；
3. IC / 分层 / 打分均可开启行业/市值中性化；
4. 单策略回测计入真实费率结构；涨停买不进、跌停卖不出、停牌顺延有测试锁定；
5. 组合回测从页面可跑通：净值 vs 基准、换手、成本、持仓变化可见，结果落库可回看。

### 1.4 AI 输出声明（沿用 V2）

本版本所有研究产物（IC / 分层 / 回测 / 组合模拟）仅供研究参考，不构成投资建议。

## 二、总体架构（V2.2 增量）

### 2.1 技术栈（无新增组件）

FastAPI + APScheduler + MySQL + backtrader（单策略路径保留）+ pandas/numpy（新增向量化研究引擎）。维持模块化单体，不引入 Redis / Celery（触发式升级结论不变）。

### 2.2 关键架构决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 研究引擎 | 新增**向量化面板引擎**（`factor_panel.py`），一次 SQL 构建日期×股票面板 | 全市场 4500 只 × 多年 × 逐股 registry.compute 不可行（每因子每股一次 DB 往返）；ic_survey 已验证面板路线 |
| 组合回测引擎 | 自研向量化（周期调仓模拟），不用 backtrader | 全市场定期调仓事件驱动跑不动；与面板引擎同构 |
| 单策略回测 | 保留 backtrader，打补丁（非对称佣金 / sizer / 可成交性守卫） | 业务优先架构缓做；改动收敛在 `strategy/base.py` + `backtest_service.py`，8 个策略文件零改动 |
| IC 落库口径 | `sa_factor_ic` 加 `pool` / `neutralized` 列并扩展唯一键 | T2.7（下轮）健康度监控需要多口径可信 IC；该表从未写入，无历史包袱 |
| 数据口径 | 维持 legacy qfq `daily_prices` | `kline_source` 切换是 V2.1 收尾事项（Runbook ④⑤⑥），不与本轮耦合 |

### 2.3 表结构变更（Alembic）

`sa_factor_ic`：
- 新增 `pool VARCHAR(8) NOT NULL DEFAULT 'current'`（current | pit）
- 新增 `neutralized VARCHAR(16) NOT NULL DEFAULT 'none'`（none | industry | industry_mcap）
- 唯一键 `uk_factor_date_horizon` → `(factor_code, trade_date, horizon, pool, neutralized)`

组合级回测**复用** `sa_backtest_run` / `sa_backtest_result`（`strategy='mf_portfolio'`，因子与治理配置存 `params` JSON，调仓记录存 `trades` JSON），不新建表。

## 三、V2.2 功能范围

### 3.1 因子与打分

#### BP-V2.2-001 · 多因子打分 V2【P0】（ROADMAP T2.1）

**用户故事**：作为量化研究者，我要在打分时显式声明每个因子的方向与权重，并可直接使用经全市场 IC 验证的 V2 反转预设，而不是靠负权重或直觉配置。

**需求点**：
1. 注册 4 个 IC 普查结论中的有效因子（口径与 `scripts/ic_survey.py` 一致）：
   - `amt20` 成交量类：20 日均成交额（(close×volume).rolling(20).mean()，流动性代理）
   - `roc120` 动量类：120 日涨跌幅（长端反转主因子）
   - `rsi14` 动量类：14 日 RSI（Wilder）
   - `skew20` 波动率类：20 日对数收益偏度
2. `/factor/score` 请求体扩展：`direction`（每因子 ±1）、`top_n`、`min_score`、`preset`；负 weight 自动等价 direction=−1（兼容存量调用方 recommend_agent）。
3. 打分管线统一为 `multi_factor.py` 路径：z-score + ±3 clip + 缺失中位数填充 + 权重归一化（弃用 factor_service 内的弱版实现）。
4. 内置预设 `v2_reversal`：amt20(0.30) + roc120(0.25) + hv20(0.20) + rsi14(0.15) + skew20(0.10)，全部 direction=−1（超跌+低波+低流动性）。

**验收标准**：上述 4 因子出现在因子字典并可算值；带 direction 的打分请求返回与手工翻方向一致的结果；preset=v2_reversal 可用；旧调用方（负 weight）行为不破坏。

### 3.2 研究基建

#### BP-V2.2-002 · 多 horizon IC 与分层回测【P0】（ROADMAP T2.3）

**用户故事**：作为量化研究者，我要看一个因子的 IC 在不同持有期下如何衰减、其五分位组合长期净值与多空价差如何，而不只是单日截面 IC。

**需求点**：
1. 新增向量化面板引擎：按日期×股票一次性构建 close/volume 面板，向量化计算面板因子；基本面因子经 stock_pool 快照 join 面板化。
2. `GET /factor/{code}/ic-series`：区间内逐调仓日（步长参数化，默认 5 日）计算 RankIC，输出逐日 IC 序列、mean/std/ICIR/胜率、**horizon=1/5/10/20 衰减曲线**、分年度 IC；结果落库 `sa_factor_ic`（含此前缺失的 ir 字段）。
3. `POST /factor/{code}/layered-backtest`：五分位等权组合净值曲线（调仓步长参数化）、多空价差（Q5−Q1）、各层年化/波动/最大回撤统计。
4. 前端因子页新增「IC 衰减」卡（多 horizon 均值 IC 柱图 + 分年 IC 表）与「分层回测」卡（五分位净值 + 多空价差 echarts）。

**验收标准**：ic-series 返回的逐日 IC 与既有单日 `compute_ic` 在同一日同口径下一致；分层回测 Q5−Q1 方向与 IC 符号一致；落库行可在表中查到。

#### BP-V2.2-003 · 中性化进研究与打分【P0】（ROADMAP T2.4）

**用户故事**：作为量化研究者，我要在 IC / 分层 / 打分时剔除行业与市值暴露，确认因子收益不是行业/风格贝塔的伪装。

**需求点**：IC 序列、分层回测、多因子打分（含组合回测内的打分）四处统一支持 `neutralize = none | industry | industry_mcap`；横截面先经 `neutralize_cross_section`（行业哑变量 + ln(市值) 回归取残差）再进 IC/分层/z-score；行业取 `sa_industry_map`（PIT effective_date），市值取 stock_pool total_mv；未覆盖行业的股票残差置 NaN（IC 自动缩样本）。

**验收标准**：开关生效（同一因子同一日，开/关中性化 IC 数值不同且样本数变化合理）；前端 SampleFilterBar 可选。

### 3.3 回测严谨化

#### BP-V2.2-004 · 单策略回测严谨化【P0】（ROADMAP T2.2）

**用户故事**：作为策略研究者，我跑的回测要计入真实交易成本、尊重涨跌停/停牌的可成交性，仓位按资金比例而不是 1 股。

**需求点**：
1. 新增共享成本模型 `cost_model.py`：佣金双边万 2.5（最低 5 元/笔）、印花税卖出单边万 5、过户费双边十万分之一、滑点参数化（默认千 1）；单策略与组合回测共用。
2. backtrader 接入非对称佣金（自定义 CommissionInfo，按 size 符号区分买卖）。
3. 可成交性约束：`SaDailyTradeStatus` 的 buy_tradable/sell_tradable（停牌、一字板）传入回测，`BaseStrategy.buy()/sell()` 在不可成交日跳过下单；状态缺行回退 K 线推断（涨跌幅撞板）。
4. **仓位模型修复（行为变更）**：现回测每笔固定 1 股；改为买入投入约 98% 可用资金、卖出清仓全部持仓。历史回测结果不可比——旧值本就失真，spec 明示不迁移。
5. 调仓频率参数化归组合回测路径（BP-005）；单策略保持信号驱动。成本与治理参数存入 run params。

**验收标准**：含涨跌停样本的回测中，涨停日买单被跳过（测试锁定）；卖出成本 > 买入成本（印花税生效）；回测交易的金额量级与初始资金一致（非 1 股）；最低佣金在小额订单上生效。

### 3.4 组合级回测

#### BP-V2.2-005 · 组合级回测产品化【P0】（ROADMAP T2.5，依赖 BP-001/002/003/004）

**用户故事**：作为量化研究者，我要把多因子打分变成一个可长期跟踪的组合策略——定期调仓、计入成本与可成交性，与基准对比净值、换手、成本、持仓变化。

**需求点**：
1. `POST /api/v1/factor/portfolio-backtest`：入参 = 因子配置（preset 或自定义 code/weight/direction 列表）+ 区间 + 调仓频率（weekly/monthly/N 日）+ top_n + 初始资金 + 成本参数 + 治理开关（pool/样本过滤/中性化/流动性预筛 top-K）+ 基准（默认 sh000001）。
2. 向量化引擎：每个调仓日，PIT 池 ∩ 样本过滤 ∩ buy_tradable ∩ 流动性预筛（amt20 top-K，默认 1000）→ 统一打分 → top-N 目标组合；换仓时卖出非目标（sell_tradable=0 顺延持有）、买入新目标（不可买跳过顺延），全程套成本模型；日度净值 = 持仓收盘市值 + 现金。
3. 产出与落库：策略/基准净值曲线、年化/波动/夏普/Calmar/最大回撤、每次调仓换手率、累计成本、持仓时间线；复用 `sa_backtest_run/result`（strategy='mf_portfolio'），可通过现有 `/backtest/{run_id}` 回看。
4. 前端 Portfolio 页新增「多因子组合回测」卡：预设/自定义因子配置、区间、频率、top_n、成本 → 提交 → 指标卡 + 净值 vs 基准 + 换手/成本 + 持仓明细。

**验收标准**：小样本端到端跑通（NAV 单调有界、成本>0、换手率∈[0,2]）；一字板持仓卖出顺延有测试；结果落库后经 `/backtest/{run_id}` 可查；前端从页面跑通全流程。
