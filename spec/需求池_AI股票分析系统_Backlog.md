## 一、文档说明

### 1.1 用途
- **集中管理**：所有非 V1 需求的唯一入口，避免散落在多个 PRD 中。
- **动态排期**：需求按版本（V1.5 / V2 / V3）和优先级分组，可随研发进展调整。
- **状态流转**：每条需求带状态字段，便于追踪从「构想 → 设计 → 开发 → 上线」全过程。

### 1.2 字段约定

| 字段 | 含义 | 取值 |
|---|---|---|
| ID | 需求唯一编号 | `BP-<版本>-<序号>`，如 `BP-V1.5-001` |
| 模块 | 所属功能模块 | 数据中心 / 数据展示 / AI 分析 / 策略 / 回测 / AI 助手 / 平台架构 |
| 优先级 | 该需求在所属版本内的优先级 | P0（必须）/ P1（应做）/ P2（可做） |
| 状态 | 当前流转状态 | 构想 / 待设计 / 设计中 / 待开发 / 开发中 / 部分上线 / 已上线 / 暂缓 |
| 来源 | 需求出处 | 原 PRD V1.1 / 用户新增 / 技术演进 |

### 1.3 版本节奏

| 版本 | 主题 | 目标 |
|---|---|---|
| **V1** | 精简 MVP | 跑通「数据→分析→策略→回测」主线（见 PRD V1.2）|
| **V1.5** | 增量完善 | 补齐数据维度与展示，丰富技术指标与情绪面（见 PRD V1.5）|
| **V2** | 量化研究平台化 | 因子库 + 多策略 + 高级回测 + RAG + 多 Agent（业务优先，见 PRD V2）|
| **V2.1** | 数据修复 | 复权根治 / PIT 股票池 / 交易状态 / 行业升级 / 质量日报（见 PRD V2.1）|
| **V2.5** | 架构升级 | Redis/Celery/ClickHouse/ES/微服务/K8s（V2 业务稳定后启动）|
| **V3** | AI 深度化 | 多 Agent 协同、AI 自主优化、模拟/实盘交易 |
