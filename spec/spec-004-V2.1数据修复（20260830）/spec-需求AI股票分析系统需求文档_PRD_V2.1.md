## 一、项目背景（V2.1 增量）

### 1.1 版本定位：为什么单开一个"数据修复"版本

V2 量化研究平台（因子库 / IC 分析 / 多因子打分 / 高级回测 / RAG / 4 Agent）已全栈上线，
8 月研究深化期完成了全市场 5 年日 K 补数（4,596 只零失败）与全市场 IC 普查。
普查过程同时对数据本身做了系统校验，**结论是：平台的瓶颈已经不是功能，而是研究结论的可信度**。

step1 报告确认的四类数据问题（V2.1 的直接立项依据）：

| # | 问题 | 规模（实测） | 对研究的影响 |
|---|---|---|---|
| 1 | 复权断裂：`daily_prices.close` 为前复权价，但历史回填与每日增量各自的复权基准不一致，分红送转后拼接处出现假跳空 | 可疑 3,394 格（0.09%）/ 2,175 只，集中于 2026-06/07 分红高峰（07-30 一天 2,027 只） | 收益序列失真，**正式回测前必须重刷** |
| 2 | 幸存者偏差：股票池为当前快照，退市股缺失 | 5,152 只池中无一只退市股 | IC 与回测系统性偏乐观 |
| 3 | 未过滤 ST / 涨跌停不可成交样本 | 无 ST/停牌/一字板标注 | 反转策略"跌停买不进"的最大执行风险未建模 |
| 4 | 行业分类仅 19 个一级类、部分为 NULL 继承 | `stock_pool.industry` 东财口径 | 无法做行业/市值中性化，因子收益混入风格暴露 |

次级问题（同报告）：amount/turnover 缺失 79%、价格冻结 576 格/141 只、整段错位 30 行/17 只、
新股上市首日极端 bar。已验证 high/low 与 close 无系统性复权错位（无需重刷全字段）。

### 1.2 版本目标（V2.1）

1. **数据可信**：四类数据问题全部闭环，复权断裂根治且有防复发机制；
2. **研究无偏**：IC / 回测可基于 point-in-time 股票池，可过滤 ST / 停牌 / 不可成交样本；
3. **质量可巡检**：数据质量检查产品化为每日调度，异常当日可见；
4. **零回归**：V2 全部已上线功能行为不变，接口向后兼容。

### 1.3 成功标准（= ROADMAP 阶段一退出标准）

出回测报告时，可以声明以下四件事，且每件都有平台功能（而非一次性脚本）支撑：

- "本回测**无复权断裂**"（全市场 close2close 与源 pct_change 偏离 >0.5% 的格子清零，见 BP-002 验收）；
- "本回测**无幸存者偏差**"（按历史时点取股票池，退市股在池，见 BP-004 验收）；
- "本回测**已处理 ST / 涨跌停可成交性**"（过滤开关生效，见 BP-005 验收）；
- "本因子收益**可做行业中性化**"（多级行业分类 + 市值序列可用，见 BP-006 验收）。

外加一条运营标准：数据质量日报上线且连续运行（见 BP-007 验收）。

### 1.4 AI 输出声明（沿用 V2）

本系统所有 AI 输出仅作研究参考，不构成投资建议。V2.1 修复的是 AI 与量化研究的**输入数据质量**，
不改变任何输出定位。

## 二、总体架构（V2.1 增量）

### 2.1 技术栈（无新增组件）

V2.1 **不引入任何新中间件**。按 ROADMAP 阶段四结论，Redis / Celery / ClickHouse / 微服务 / K8s
全部转触发式；V2.1 期间长任务（全历史重刷、历史回补）用**进程内异步执行 + 任务状态记录**实现
（现有 APScheduler + `sa_admin_task_log` 体系扩展），这是 ROADMAP T4.1"任务状态化"的最小前置版本。

| 数据库 | MySQL `stock_analysis` | 新表全部 `sa_` 前缀，Alembic 管理 |

### 2.3 数据层目标设计

#### 2.3.1 新建表（全部 `sa_` 前缀，Alembic 管理）

| 新表 | 用途 | 对应需求 |
|---|---|---|
| `sa_kline_daily` | **不复权**日 K（OHLC、volume、amount、turnover、pct_change），平台自有，唯一键 (stock_code, trade_date) | BP-001 / 002 / 008 |
| `sa_adjust_factor` | 按日累计复权因子（每股每日一行，除权日跳变）；后复权价 = 不复权价 × 因子 | BP-001 |
| `sa_stock_lifecycle` | 股票生命周期（stock_code、list_date、delist_date、list_status），point-in-time 宇宙的依据 | BP-004 |
| `sa_daily_trade_status` | 交易状态（is_st、is_suspended、涨跌停类型、buy/sell_tradable），按 (stock_code, trade_date) | BP-005 |
| `sa_industry_map` | 行业映射（industry_code 稳定编码 + 一级/二级行业名 + 来源 + 生效日期），统一两套旧口径 | BP-006 |
| `sa_data_quality_check` | 每日质量巡检结果（check_date、check_name、metric、status、明细引用） | BP-007 |

> 完整 DDL 在配套实现方案中给出（本 PRD 只定义字段意图与验收）。

#### 2.3.2 存储迁移策略（BP-001 的方案约定）

`daily_prices` 是外部遗留表且被全部下游消费，**不在原表上改语义**。迁移路径：

1. 新建 `sa_kline_daily`（不复权）+ `sa_adjust_factor`，由重刷任务灌入全历史（见 BP-002）；
2. 读取层 `market_service.get_kline` 增加 `adjust` 参数，从新表按需折算前/后复权，**默认返回口径与现状一致（前复权）**，下游零改动；
3. 每日增量同步（17:30）与 23:00 自愈、`history_backfill` 的写入目标切换到新表（同步写不复权价与当日因子）；
4. 灰度期新旧表并行校验（抽样比对折算后 close 与旧表 close），校验通过后 `daily_prices` 停写、保留只读一个版本，随后退役。

**研究口径约定**：因子 / IC / 回测计算默认**后复权**（收益序列稳定，不随未来除权变化）；
前复权仅用于 K 线展示。该约定写入读取层默认值，阶段二（V2.2）的研究产品全部遵循。

#### 2.3.3 管线变更（写入侧防线）

```text
交易日 17:30  daily_k_sync          → 写 sa_kline_daily（不复权）+ sa_adjust_factor（当日因子）
                                   └─ 检测当日因子相对昨日跳变（除权事件）→ 触发该股全历史重刷任务
交易日 23:00  daily_k_sync_retry    → 自愈逻辑不变（行数基线比对 + 失败重放），目标表切换
每日 08:00    data_quality_check ★  → step1 校验逻辑产品化（BP-007）
按需（admin）  daily_k_repair ★      → 一次性修复脚本产品化：指定股票/日期段重抓（BP-003）
```

### 2.4 长任务异步化（admin 体系最小扩展）

全历史重刷（~2,400 只）与历史回补远超 `run_task` 300s 超时。V2.1 做最小改造：
`run_task` 支持**后台线程执行 + 状态轮询**（运行中/进度/完成/失败），任务状态与进度写入
`sa_admin_task_log`（扩展字段），admin 前端任务列表展示进度。不引入 Celery（触发式结论不变，
与 ROADMAP T4.1 衔接：此处即"最小 job 记录"）。

### 3.1 数据修复

#### BP-V2.1-001 · 复权体系重构【P0】（ROADMAP T1.1）

- **背景**：`daily_prices.close` 前复权、多批次基准不一致，2026-06/07 分红高峰产生 3,394 格假跳空。
  在原方案下，**未来每次分红都会复发**（增量以新基准写、历史还是旧基准）。
- **目标**：根治复权问题——存储不复权价 + 复权因子，读取层按需折算，并建立除权事件防复发机制。
- **功能点**：
  1. 新建 `sa_kline_daily`（不复权）与 `sa_adjust_factor`（按日累计因子），DDL 走 Alembic；
  2. 读取层 `get_kline`（及 IC / 回测 / AI 分析取数路径）增加 `adjust: qfq | hfq | raw` 参数，
     默认 qfq 保持现状兼容；研究计算内部默认 hfq（§2.3.2 约定）；
  3. 写入链路切换：17:30 增量、23:00 自愈、`history_backfill` 写新表（不复权价 + 当日因子）；
  4. **除权事件防线**：每日增量后检测因子跳变，跳变即自动触发该股全历史重刷（复用 `history_backfill` upsert 路径），
     保证单股序列始终单一基准；
  5. 方案评审记录入 docs（存储选型、迁移步骤、回滚方案）。
- **验收**：
  - 任一股票 `raw × 因子` 折算的后复权 close，其 close2close 与源 `pct_change` 偏离 >0.5% 的格子数为 0（全市场）；
  - 读取层三种 adjust 口径可用，默认口径下 V2 已上线接口返回值与迁移前一致（抽样 100 只比对）；
  - 人为构造一次除权事件（或以 2026 年内真实分红股验证），重刷自动触发且拼接处无假跳空；
  - 迁移可回滚：切换读取前新表数据完整、旧表未被破坏。
- **依赖**：无。

#### BP-V2.1-002 · 全市场历史重刷【P0】（ROADMAP T1.2）

- **背景**：3,394 格污染集中在 2,175 只（07-30 一天 2,027 只）。重刷全历史可让单股序列回归单一复权基准。
- **目标**：把受污染股票的完整历史重刷进 `sa_kline_daily`，作为新表首次全量灌入的第一批。
- **功能点**：
  1. 以 `check_adjustment.py` 逻辑（产品化后见 BP-007）圈定重刷清单（预计 ~2,400 只）；
  2. 批量执行全历史重抓（akshare 主源 + 腾讯兜底，复用 `history_backfill` 的 upsert 与断点续跑能力），
     走 §2.4 长任务异步化；
  3. 其余股票滚动灌入新表（不阻塞验收：验收只要求受污染清单完成）。
- **验收**：
  - 重刷清单内股票，close2close 与源 pct_change 偏离 >0.5% 的格子**清零**（07-30 / 07-01 / 07-27 / 06-29 四个高峰日逐日核对）；
  - 重刷过程幂等可断点续跑，失败股票清单可导出并单独重放；
  - 全程数据源失败不阻断（多源降级链生效）。
- **依赖**：BP-001（表与写入路径就绪）。

#### BP-V2.1-003 · 脏数据修复产品化【P1】（ROADMAP T1.3）

- **背景**：价格冻结 576 格 / 141 只（降级源坏数据，如 001331）；整段价格错位 30 行 / 17 只（如 600066 在 2022-04~08）。当前修复靠手工脚本。
- **目标**：存量脏数据清零，修复动作从脚本变为 admin 可操作的任务。
- **功能点**：
  1. 生成修复清单（冻结 / 错位两类，含股票与日期段），按清单用腾讯双 host 重抓并 UPSERT（产品化 `repair_tencent_only.py`）；
  2. 新增 admin 任务 `daily_k_repair`（参数：股票列表或清单类型），异步执行（§2.4）；
  3. 修复后由质量巡检（BP-007）复扫确认。
- **验收**：
  - 576 格冻结与 30 行错位全部修复或明确归因（个别无法修复的记录原因）；
  - admin 可手动触发修复任务并查看进度与结果；
  - 修复逻辑有测试覆盖（冻结/错位检测函数）。
- **依赖**：无（与 BP-001 并行，先修 `daily_prices` 亦可，新表灌入时自动获得干净数据）。

### 3.2 研究样本治理

#### BP-V2.1-004 · Point-in-time 股票池【P0】（ROADMAP T1.4）

- **背景**：`stock_pool` 为每日快照、退市股静默退出，5 年回看窗口的宇宙不含已退市股票，IC 与回测系统性偏乐观。
- **目标**：建立含退市股的生命周期表，IC / 回测支持按历史时点取池。
- **功能点**：
  1. 采集退市股票名单（含退市日期，akshare 沪深退市列表 + 东财补漏），连同在市股写入 `sa_stock_lifecycle`；
  2. 提供 point-in-time 取池服务：`get_pool_asof(date)` = 该日已上市且未退市的全部股票（含此后退市者）；
  3. IC 普查与回测的股票池来源切换为该服务（开关保留"当前快照"模式以对照）。
- **验收**：
  - `sa_stock_lifecycle` 覆盖 2021-06 以来退市的 A 股（数量与交易所披露口径核对，差异可解释）；
  - 任取历史日期（如 2022-06-30），取池结果包含当时在市、其后退市的股票；
  - 用 PIT 池重跑一次 IC 普查，输出与旧池的差异对比（预期反转类因子 IC 绝对值下降但仍显著——这是修复的目的，不是回归）。
- **依赖**：无。

#### BP-V2.1-005 · 交易状态标注与可成交性【P0】（ROADMAP T1.5）

- **背景**：无 ST / 停牌 / 一字板标注。反转策略信号常出现在跌停股上，"跌停买不进"未建模，回测收益虚高。
- **目标**：日频数据具备交易状态维度，IC 与回测支持过滤开关。
- **功能点**：
  1. 新建 `sa_daily_trade_status`，字段：`is_st`、`is_suspended`、`limit_status`（无 / 涨停 / 跌停 / 一字涨停 / 一字跌停）、
     `buy_tradable`、`sell_tradable`；
  2. 判定口径：
     - **一字板 / 涨跌停**：由日 K OHLC 与前收盘推导（开=高=低=收且触及涨跌停价 → 一字板），纯计算可回填全历史；
     - **停牌**：当日 `stock_pool` 快照在池但无行情行；
     - **ST**：历史时点名称含 "ST"（`stock_pool` 历史快照可回溯部分年份）+ 当前 ST 名单回溯；数据源无法覆盖的早期年份，标注缺失并在过滤开关中显式声明覆盖率；
  3. 全历史离线回填 + 每日增量计算（挂在 17:30 同步之后）；
  4. IC 与回测服务增加过滤参数：`exclude_st`、`exclude_suspended`、`only_tradable`（买入侧）。
- **验收**：
  - 涨跌停/一字板标注回填后，抽 20 个人工核对日（含 2026-07 极端行情日）准确率 ≥ 95%；
  - 回测接口带过滤开关运行同一策略，输出与不过滤的差异报告（换手、成本、收益变化）；
  - 停牌日不产生成交（回测撮合约束的前置数据，阶段三 T3.3 消费）。
- **依赖**：无。

#### BP-V2.1-006 · 行业分类升级与中性化基础【P1】（ROADMAP T1.6）

- **背景**：行业仅 19 个一级类（东财口径），且 `stock_pool.industry`（快照继承，NULL 传播）与 `sa_stock_industry`（个股页）两套口径并存；无行业/市值中性化能力，因子收益混入风格暴露。
- **目标**：统一到一套多级行业分类（稳定编码），并提供中性化所需的市值序列——为 V2.2 的 T2.4（中性化进研究与回测）打数据基础。
- **功能点**：
  1. 新建 `sa_industry_map`：industry_code（稳定编码）、一级 / 二级行业名、来源（申万优先，东财兜底）、生效日期；
     同步任务采集申万一级/二级成分（akshare），失败降级东财行业板块成分；
  2. 统一读取口径：股票列表筛选、因子分组展示从新表取行业；`stock_pool.industry` 与 `sa_stock_industry` 降级为兼容来源，逐步停用；
  3. 提供逐日流通市值序列（中性化的市值因子）：优先 amount/turnover 推导，amount 缺失期用不复权 close × 当期股本近似（近似段打标）；
  4. 中性化**计算能力**落地（横截面回归取残差的工具函数 + 单测），产品化开关在 V2.2 T2.4 接入三处（IC / 分层 / 回测）。
- **验收**：
  - 行业映射覆盖全市场 ≥ 95%，一级行业数 31（申万）或 ≥ 19 且粒度显著提升（东财降级时）；
  - 退市股亦有行业归属（PIT 池内可分组）；
  - 市值序列与当日 `stock_pool.total_mv / circ_mv` 抽样比对，偏离 >10% 的比例 < 5%；
  - 中性化工具函数通过构造用例单测（注入已知行业/市值效应后残差应消除该效应）。
- **依赖**：无（市值序列质量受益于 BP-008 回补，但可用近似口径先行）。

### 3.3 质量运营

#### BP-V2.1-007 · 数据质量日报【P0】（ROADMAP T1.7）

- **背景**：step1 的校验（复权断裂 / 冻结 / 缺失扫描）是一次性脚本；四类问题中任何一类复发都无法当日发现（分红高峰污染积累了一个多月才被研究侧察觉）。
- **目标**：校验逻辑产品化为每日调度，结果落库、可视、告警。
- **功能点**：
  1. 每日 08:00 调度 `data_quality_check`，检查项与阈值（可配置）：
     - 复权一致性：当日新增行 close2close vs pct_change 偏离 >0.5% 计数；
     - 价格冻结：近 5 日 close 与 pct_change 均不变的股票数；
     - 行数基线：当日入库行数 / 快照池规模 比值（复用 23:00 自愈的 `_COMPLETENESS_RATIO` 口径）；
     - 字段缺失率：amount / turnover 缺失占比（BP-008 后应显著下降）；
     - 标注覆盖率：trade_status / 行业映射 / 生命周期表的当日覆盖率；
     - 错位异常：单日振幅超过阈值（如 >30%）的行数；
  2. 结果写 `sa_data_quality_check`（每日每项一行：指标值、阈值、通过/警告/失败）；
  3. admin 新增"数据质量"页签：当日红绿灯总览、30 日趋势、异常明细（股票级）导出；
  4. 告警：失败项写调度日志 ERROR + admin 页红色标记（邮件等外发渠道留待阶段三 T3.6 统一做）。
- **验收**：
  - 连续 5 个交易日自动出报告，历史可查；
  - 人为注入坏数据（删一行/改一个 close），次日报告能捕获并定位到股票级；
  - 阈值配置修改无需改代码（配置表或 settings）。
- **依赖**：BP-002（基线先干净，否则日报长期红灯失去信号价值）。

#### BP-V2.1-008 · amount / turnover 历史回补【P2】（ROADMAP T1.8）

- **背景**：两列 79% 缺失，量类因子（含 IC 最强因子 amt20）被迫用 volume×close 替代口径；市值序列推导（BP-006）同样受限。
- **目标**：历史成交额/换手率回补，量类因子与市值推导摆脱替代口径。
- **功能点**：
  1. 对缺失日期段用腾讯 kline（尾部字段含成交额）+ 东财日线双源回补，走长任务异步；
  2. 回补后量类因子口径统一切换（amt20 等改用真实 amount，IC 结论需复核方向不变）。
- **验收**：
  - 全市场 amount/turnover 缺失率 79% → ≤ 10%（剩余缺失逐段归因）；
  - 回补后重跑 amt20 的 IC，方向与显著性不变（变则出具对比说明）。
- **依赖**：无（建议在 BP-002 重刷时顺带完成，同批次请求可复用）。

## 四、非功能性需求（V2.1）

### 4.1 数据源保护

- 全历史重刷 ~2,400 只 + 滚动灌入 5,152 只：分批限速，akshare 与腾讯双源轮换，单源连续失败自动切换（沿用现有降级链与 retry 机制）；
- 长任务可暂停/恢复，中断后不重复请求已完成股票（断点续跑状态落库）。

### 4.2 幂等与可回滚

- 所有重刷 / 回补 / 修复任务幂等（唯一键 upsert），重复执行结果一致；
- 存储迁移期间旧表只读保留，读取切换点可回退（配置开关）。

### 4.3 性能（不退化）

| 项 | 要求 |
|---|---|
| `get_kline` 增加复权折算后 | 单股一年数据 < 500ms（P95），与现状持平（因子计算向量化折算） |
| IC / 回测（带过滤开关） | 相比现状增幅 < 30%（trade_status 关联查询走索引） |
| 质量巡检每日运行 | 全量检查 < 10 分钟（MySQL 侧聚合，避免全表扫描进 Python） |

### 4.4 兼容性

- V2 已上线接口的默认行为零变化（复权口径默认 qfq、股票池默认当前快照——PIT 与过滤均为显式参数）；
- `daily_prices` / `stock_pool` 在灰度期内保持可读，下游任何组件不直接感知新表存在（统一经 `market_service`）。

### 4.5 合规

- 数据源仍限公开授权渠道（akshare / 腾讯 / 东财公开接口）；退市名单、行业成分为公开信息；
- V2.1 不涉及任何交易接口。

## 七、优先级与排期建议

> 对齐 ROADMAP：阶段一 ~3 周（2026-09），里程碑 M1 = 2026-09 中"数据可信"。单人节奏，可伸缩。

| 批次 | 需求 | 说明 |
|---|---|---|
| 第 1 周 | BP-001（评审+建表+写入链路+读取层）、BP-004（生命周期表+PIT 取池）、BP-005（状态标注回填） | 三条互不依赖，可并行；§2.4 长任务异步化随 BP-001 先行 |
| 第 2 周 | BP-002（2,400 只重刷+滚动灌入）、BP-003（脏数据修复产品化） | 重刷是本周主体；003 可穿插 |
| 第 3 周 | BP-006（行业映射+市值序列+中性化工具）、BP-007（质量日报）、全量校验收尾 | 007 依赖 002 完成后基线干净；P2 的 BP-008 视带宽并入第 2 周重刷批次或顺延 |

依赖关系：BP-002 → BP-001；BP-007 → BP-002；BP-006 的市值序列 ← BP-008（软依赖，近似口径可先行）；
其余无强依赖。**砍单顺序**（带宽不足时）：BP-008（P2）→ BP-003 的"产品化"部分保留清单执行、
admin 化顺延；BP-001/002/004/005/007 主线不动。

## 八、版本边界与不做的事（V2.1 Out-of-Scope）

- ❌ 新因子、新策略、新回测指标 → V2.2（阶段二）
- ❌ 多因子方向/权重按 IC 结论重构 → V2.2 T2.1（V2.1 只提供干净数据与过滤开关）
- ❌ 中性化在 IC / 分层 / 回测三处的产品化开关 → V2.2 T2.4（V2.1 只交付数据与计算工具）
- ❌ 新业务页面（数据质量日报 admin 页签除外）
- ❌ Redis / Celery / ClickHouse / 微服务 / K8s → 全部触发式（ROADMAP 阶段四结论），长任务用进程内异步
- ❌ 模拟盘 / 实盘 → 阶段三及以后
- ❌ 分钟级数据治理（本轮只管日频）
